Branch: `feature/v72.2-smart-ocr`. Stable remains v72.1. All production OCR
changes are self-contained in `releases/RAILY_SmartScan_v72_2.py`.

SHA-256:
`8062686fca17e85df687317cc004578a522f22cafe05cccc66538e95325f8126`

Run from the repository with Pillow, PyMuPDF, pytesseract and Tesseract installed:

```text
python tests/test_v72_2.py --ocr --output <scratch-folder>
```

The harness extracts definitions through AST rather than starting RAILY, so it
does not load or modify installed user data. It generates fixtures, old raw OCR,
new structured previews and a JSON results file in the requested scratch folder.
Full-file AST compilation and py_compile passed on 2026-09-13.

## Results

All seven layouts correctly produced Name, Start Date and Location: clean print,
handwriting-style values, ruled table, 3-degree rotation, poor contrast, crossed
date, and values below labels in adjacent columns. Normal fixtures took about
1.45–2.07 seconds with no additional field OCR calls. The crossed date took
4.05 seconds and four field calls, succeeding with blue-ink line repair.

| Comparison fixture | v72.1 raw OCR extraction | v72.2 structured extraction |
| --- | --- | --- |
| Date crossed by a rule | Start Date unread | Start Date: 2024-06-03 |
| Adjacent columns, values below labels | Location empty | Location: West Yard |

The names and locations are fixture data only; the engine contains no expected
person or location values. Table columns use visible separators in the preview,
and low-confidence fragments are excluded from reliable text.

Handwriting-style `6/3/24`, `06/03/2024`, `9/12/26` and `6-17-26` each took two
calls (about 0.52–0.56 seconds). A taught date crossed by a black rule took 18
calls and 5.11 seconds, succeeding through blue-ink line repair. Printed
`09/12/2026`, `9/12/26`, `09-12-2026` and `2026-09-12` each took exactly two
calls in both v72.1 and v72.2. Mock checks also verify fast-path configuration
equivalence, rejection and attempt limits; a deadline test bounds slow fallbacks.

Regression checks cover confidence-gated metadata, trusted Start Date fallback
and explicit date preference preservation, native PDF text reuse, shared render
cache/copy isolation, background review preparation and cancellation after a
selection change. Protected learning, manual dates, duplicate detection, splitting,
backup and visual-signature functions and the Teach sizing/scroll helpers remain
AST-equivalent. Other App methods are unchanged. The complete source diff was
reviewed; earlier releases and update_manifest.json remain byte-for-byte unchanged.

## Limits

Fixtures use Arial and Segoe Print, not real handwritten scans. This verifies
layout handling and bounded preprocessing, not general handwriting accuracy.
Tesseract confidence and repeated recognition are heuristics; uncertain required
dates still require Teach/Review. Orientation and table separation are conservative
heuristics, not a full document-layout model. Live Windows interaction was not
retested for v72.2; existing v72.1 scrolling code is preserved and regression-checked.
No stable update or deployment is performed by this feature branch.
